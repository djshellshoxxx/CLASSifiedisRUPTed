## Requirements and typed data
- PS-002-01.R01: Unlocked local principal creates one private draft in its own IndexedDB vault. Client allocates random UUIDv4, collision-checks locally, sets owner_principal_id from vault context, local revision 1/economic_revision 1 (economic_digest absent until reviewed signing) and advisory client timestamps. No tenant/account/session dependency.
- PS-002-01.R02: Input `{kind:sell|wanted|giveaway,title?,description?,condition?,public_area_id?,quantity?,price?,price_on_request?}` only. CL-001 defines exact limits/defaults: title if present 3..120 NFC code points, description <=10000, quantity integer 1..100000, area approved coarse code 3..64, paired currency/positive minor-unit decimal string <=9e15, price_on_request false default. Draft can omit title/area/price; wanted/giveaway prohibit price/price_on_request. Reject caller owner/id/state/revision/vault and precise contact/coordinate fields.
- PS-002-01.R03: `objects` key `[listing,id]`, value CL-001 owned listing; `commands` key `[principal_id,listing.create,command_id]`; event key event_id. One IndexedDB readwrite transaction validates local owner/policy and writes object, receipt and local event/outbox atomically. No SQL FK or central user record. Crypto/key protection is review-blocked; secret handles never copied to listing.
- PS-002-01.R04: Draft always private; F06 projection excludes it. Published requires title/area and sell price or price_on_request. Minor units remain canonical strings/BigInt arithmetic, never floating point. Client timestamps/IDs confer no global authority.
