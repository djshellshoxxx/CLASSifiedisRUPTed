## Requirements

- **PS-013-01.R01** A TradeLeg stores giver, receiver, 1..5 item lines (1 line in cycles), the listing cid and listing revision hash seen when defined, declared value from the owner's ItemValuation and the subject reference.
- **PS-013-01.R02** Legs are immutable after definition; their only mutable fields are status and the referenced marker.
- **PS-013-01.R03** Legs are P2 and are exchanged only inside signed ProposalRevision snapshots, where receivers materialize their own read-only copies with provenance.

## Specification

### TradeLeg

Schema `classrup.mutiny.trade_leg/v1` · storage **device** · privacy **P2** · retention **RET-EVIDENCE**

| Field | Type and constraints |
|---|---|
| id | uuidv7 — primary key; generated by the defining author |
| tenantId | uuidv7 — vault tenant scope |
| subjectType | enum — trade_proposal \| cycle |
| subjectId | uuidv7 — subject this leg belongs to |
| position | int — 0..7; order in the cycle ring, 0 or 1 for direct proposals |
| giverId | did — item owner |
| receiverId | did — receiving party; differs from giverId |
| items | array — 1..5 lines (1 in cycles) {inventoryItemId uuidv7, listingCid cid, listingRevisionHash cid, variantId? uuidv7, quantity int 1..99, declaredValue Money, valuationId? uuidv7} |
| legValue | Money — sum of declared values in the leg currency; single currency per leg |
| basis | enum — local_inventory \| signed_listing — how availability was verified when defined |
| status | enum — defined \| referenced \| voided |
| origin | enum — local \| peer |
| provenance? | object — {revisionId, receivedAt} for peer-materialized legs |
| revision | int — CTR-ID-001 ID-4 |
| createdAt | timestamp — RFC 3339 UTC |
| updatedAt | timestamp — RFC 3339 UTC |

**Invariants**
- giverId differs from receiverId and all inventoryItemIds within a subject are distinct across legs.
- A leg in a cycle has exactly one item line with quantity 1; a leg in a direct proposal has at most 5 lines.
- items, giverId, receiverId and declaredValue never change after definition; status moves only forward.
- A leg referenced by a sealed revision cannot be voided.

### Storage DDL

```sql
  giver_id TEXT NOT NULL, receiver_id TEXT NOT NULL, status TEXT NOT NULL, revision INTEGER NOT NULL, data TEXT NOT NULL);
CREATE INDEX mutiny_leg_subject ON mutiny_trade_leg(tenant_id, subject_id, status);
```
