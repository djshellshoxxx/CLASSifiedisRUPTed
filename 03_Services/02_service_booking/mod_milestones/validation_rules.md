# PS-031-02 — validation rules

**Status:** SPECIFIED — Stage 3 draft, pending review.
**Requirement ID:** PS-031-02. **Owner:** [03_Services/02_service_booking/mod_milestones](SPEC.md). **Implementing module:** 03_Services/02_service_booking/mod_milestones. **Consumers:** F07 identity, F10 privacy, F15 platform, F16 security (per [dependency matrix](../../../DEPENDENCY_MATRIX.md)); mod_quotes (PS-032) and mod_disputes (PS-030) through their query and event contracts.

## Purpose and scope
Business outcome: every write is checked against exact, documented rules before any state change, so that an invalid plan, an unauthorized party or a stale revision never changes a record. Each rejection returns one typed error code from the table below.

Exclusions: state transitions themselves are in workflow_state_machine.md; authorization matrix in authorization_capabilities.md; the rules here do not judge the quality of deliverables or the fairness of a price.

## Requirements
- PS-031-02.R01: Validation runs in this order and stops at the first failure: (1) request size and JSON shape, (2) idempotency key, (3) authentication and blocked-account check, (4) capability check, (5) resource existence and party check, (6) optimistic-lock and revision check, (7) field rules, (8) plan-level rules, (9) state guard. Order is fixed so that error codes do not leak existence to non-parties.
- PS-031-02.R02: Failure cases covered: missing field, wrong type, out-of-range value, duplicate sequence, stale revision, repeated key with different body, concurrent write on same plan, submission after limit, dispute-blocked action, expired due date, adversarial input (control characters, bidirectional override characters, oversized JSON, non-https URI, unknown enum value, extra unknown field).
- PS-031-02.R03: Validation cost budget: all checks for a 50-item plan complete in p95 20 ms server time excluding database round trips. Errors are returned in the user's locale through codes only; no free-text error strings are generated by this module.

## Input normalization
- Strings: Unicode NFC; leading and trailing whitespace trimmed; internal runs of spaces collapsed to one. Control characters U+0000 to U+001F and U+007F to U+009F, plus bidirectional controls U+202A to U+202E and U+2066 to U+2069, are rejected.
- Timestamps in requests are rejected unless RFC 3339 UTC with `Z`. Dates are `YYYY-MM-DD`.
- Unknown fields in a request body are rejected (`MILESTONES_VALIDATION_SCHEMA_INVALID`), never silently dropped.

## Field rules
| Rule | Applies to | Error code when violated |
|---|---|---|

## Plan-level and state rules
- Plan has at most one non-terminal plan per booking_ref: `MILESTONES_PLAN_ALREADY_EXISTS` (409).
- Edits to items are allowed only in plan_state `draft`, or as part of a revision in `proposed`. Otherwise `MILESTONES_PLAN_NOT_EDITABLE` (409).
- Milestone field edits are allowed only while milestone_state is `pending`. Any row in `in_progress`, `submitted`, `rejected`, `disputed`, `accepted`, `expired` or `cancelled` is immutable: `MILESTONES_ITEM_IMMUTABLE` (409).
- Propose requires at least one item and all rules above passing: `MILESTONES_NO_ITEMS`, `MILESTONES_AMOUNT_SUM_MISMATCH`.
- Consent must reference the current `proposed_revision` and its digest: `MILESTONES_CONSENT_DIGEST_MISMATCH` (409) if the digest in the request differs from the stored digest; `MILESTONES_REVISION_STALE` (409) if the revision number is not the pending one.
- Submit requires `submission_count` < 5: `MILESTONES_SUBMISSION_LIMIT_REACHED` (409). Requires no open dispute on the item: `MILESTONES_DISPUTE_OPEN` (409).
- Reject requires a `reason_code`: `MILESTONES_REASON_CODE_INVALID` if absent or outside enum.
- Mutual cancel confirm requires a pending, unexpired request by the other party: `MILESTONES_CANCEL_REQUEST_NOT_FOUND` (404), `MILESTONES_CANCEL_REQUEST_EXPIRED` (409).
- Mutual cancel request is refused while any item is `disputed`: `MILESTONES_DISPUTE_OPEN` (409).

## Assumptions and open decisions
- A-MILESTONES-03: Limits are 50 items, 5 submissions per item, title 120, description 1000, note 500, reason text 500, request 128 KiB, revision content 256 KiB, due-date horizon 2 years.
- A-MILESTONES-05: Sequencing enum includes `parallel`; it can only change through a revision.
- A-MILESTONES-02: Booking and quote eligibility is decided by their owners; this module only calls the query.
- Open: exact allow-list of currencies (operator configuration, default empty = reject all); error envelope shape depends on CTR-ERR-001, which is not yet approved.
