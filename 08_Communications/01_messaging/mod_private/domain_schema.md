## Requirements

- **PS-060-01.R01** A Message is a vault record holding plaintext, the signed envelope (nonce, ciphertext, signature), the per-recipient wrapped keys, the per-sender sequence number and the sync state, with tenant and revision per CTR-ID-001; plaintext never leaves the vault except inside the encrypted envelope.
- **PS-060-01.R02** Cryptographic construction is fixed for v1 as a random 32-byte message key encrypting padded plaintext with XChaCha20-Poly1305 (additional data thread ID, message ID, sender device ID) and wrapped per recipient device by x25519 ECDH with a fresh ephemeral key, HKDF-SHA256 and XChaCha20-Poly1305, using @noble/curves and @noble/ciphers 2.4.0.
- **PS-060-01.R03** Messages are P2; the relay stores only a MailboxEnvelope (ciphertext plus routing metadata) under RET-SHORT for at most 30 days, while vault Messages follow RET-STANDARD under the user's control.
- **PS-060-01.R04** Timestamps from other parties are claims; the vault stores the sender's createdAt as a claim, its own receivedAt, and the relay-signed receipt time as evidence of that relay's clock only.

## Specification

### Message

Schema `classrup.comms.message/v1` · storage **device** · privacy **P2** · retention **RET-STANDARD**

| Field | Type and constraints |
|---|---|
| id | uuidv7 — primary key, generated by the sender vault |
| tenantId | uuidv7 — relay or community scope the thread belongs to, per CTR-ID-001 |
| threadId | uuidv7 — ref F08.S01.M02 Thread; must be active |
| direction | enum — outbound \| inbound |
| senderDid | did:key — author principal |
| senderDeviceId | uuidv7 — device whose Ed25519 key signed the envelope |
| seq | int — per-sender, per-thread counter starting at 1; with prev forms the author chain of CTR-FED-001 FED-3 |
| prev? | string — sha256 cid of the sender's previous message in the thread |
| alg | enum — xchacha20poly1305-x25519-v1 (only value in v1) |
| nonce | bytes — 24 bytes base64url |
| ciphertext | bytes — base64url, 17..12 288 bytes (padded plaintext 1..8 192 plus 16-byte tag, padded to 256-byte buckets) |
| wrappedKeys | array — 1..64 items { recipientDeviceId, ephemeralPub (32 bytes), nonce (24 bytes), wrappedKey (48 bytes) }; not covered by the sender signature because each wrap is authenticated by its own AEAD |
| senderSignature | bytes — Ed25519 64 bytes over JCS of the signed statement classrup.comms.message/v1 (envelope minus wrappedKeys and sig) |
| body? | string — plaintext, 1..8 192 bytes UTF-8; present in the vault only |
| replyToId? | uuidv7 — message in the same thread |
| receiptsRequested | boolean — sender asks for receipts; recipients may ignore |
| syncState | enum — local_committed \| prepared \| transport_acknowledged \| peer_accepted \| failed (outbound only) |
| status | enum — active \| quarantined \| deleted |
| createdAtClaim | timestamp — sender clock, a claim |
| receivedAt? | timestamp — local clock at inbound verification |
| relayReceipt? | object — { relayId, receivedAt, sig } relay-signed evidence of the relay clock only |
| deletedAt? | timestamp — set when status is deleted |
| revision | int — CTR-ID-001 ID-4 |

**Invariants**
- An inbound Message is stored active only after its signature verified against a device key listed for senderDid and its sender is a current participant of the thread; otherwise it is quarantined with a reason.
- (threadId, senderDid, seq) is unique; a second envelope with the same triple and a different cid is a fork and freezes the thread for review instead of overwriting.
- status deleted implies body, ciphertext and wrappedKeys are erased and only id, threadId, senderDid, seq and deletedAt remain.
- syncState never moves backwards and peer_accepted requires a signed acknowledgement statement from the recipient.

### MailboxEnvelope

Schema `classrup.comms.mailbox_envelope/v1` · storage **relay** · privacy **P2** · retention **RET-SHORT**

| Field | Type and constraints |
|---|---|
| id | uuidv7 — relay-assigned |
| mailboxId | string — 128-bit random identifier owned by one recipient at this relay, base64url |
| messageId | uuidv7 — copied from the signed envelope for deduplication |
| senderDid | did:key — visible routing metadata, honestly disclosed |
| size | int — 1..16 384 bytes |
| blob | bytes — the per-recipient envelope, opaque ciphertext |
| receivedAt | timestamp — relay clock |
| relayReceiptSig | bytes — relay Ed25519 signature over (mailboxId, messageId, receivedAt) |
| expiresAt | timestamp — receivedAt + 30 days |

**Invariants**
- At most one MailboxEnvelope per (mailboxId, messageId).
- A mailbox holds at most 1 000 envelopes and 20 MiB; further puts return COMMS_MAILBOX_FULL.
- The relay never stores a decryption key or plaintext and never modifies blob.

### MessageReceipt

Schema `classrup.comms.message_receipt/v1` · storage **device** · privacy **P2** · retention **RET-SHORT**

| Field | Type and constraints |
|---|---|
| messageId | uuidv7 — ref Message |
| recipientDid | did:key — who acknowledged |
| kind | enum — delivered \| read |
| signedAt | timestamp — recipient clock, a claim |
| sig | bytes — Ed25519 over JCS of statement classrup.comms.message_receipt/v1 |

**Invariants**
- At most one receipt per (messageId, recipientDid, kind) and a receipt is only stored when its signature verifies.
