# PS-109-04 — commands, queries and events

**Status:** SPECIFIED — Stage 3 draft, pending review. **Requirement ID:** PS-109-04. **Owner:** [14_Accessibility/01_a11y/mod_keyboard](SPEC.md). **Implementing module:** 14_Accessibility/01_a11y/mod_keyboard. **Consumers:** F07 (caller identity), F10 (export, retention, deletion scheduling), F15 (event envelope CTR-EVT-001, schema registry CTR-SCH-001, error envelope CTR-ERR-001), F16 (capability checks CTR-CAP-001); client keyboard runtime.

## Purpose and scope
Define the external contract of the keyboard preference module: commands that change state, queries that read it, and the domain events emitted after commit. Transport is HTTPS JSON under `/v1/keyboard/`. Field definitions come from [domain_schema.md](domain_schema.md); validation codes from [validation_rules.md](validation_rules.md).

**Business outcome:** the client can read, change, reset, roll back and delete keyboard preferences through a stable, versioned contract, and downstream consumers learn of changes through events that carry no shortcut contents.

**Exclusions:** no contract for feature actions that shortcuts invoke; no direct database access; no screen reader or WCAG contracts.

## Requirements
- **PS-109-04.R01** — Outcome: each command returns either the committed profile or one error code; each event corresponds to one committed revision.
- **PS-109-04.R02** — Cases: normal (get, update, reset, delete, rollback); invalid (see validation codes); expired (queued write older than 7 days is never sent); duplicate (same Idempotency-Key replayed); concurrent (stale expected_revision); offline (commands are queued by the client, PS-109-06); adversarial (account_id in body, extra fields, oversized body, replayed key with changed payload).
- **PS-109-04.R03** — Budgets: query p95 150 ms, command p95 300 ms server-side; event emission within 1 s of commit (outbox, PS-109-06).
- **PS-109-04.R04** — Command and query signatures (commands take caller context from the authenticated session, never from the body):
  - `GetKeyboardProfile(caller) -> ProfileResult` (query, `GET /v1/keyboard/profile`)
  - `UpdateKeyboardProfile(caller, idempotency_key, expected_revision, patch) -> ProfileResult` (command, `PATCH /v1/keyboard/profile`)
  - `ResetKeyboardProfile(caller, idempotency_key, expected_revision) -> ProfileResult` (command, `POST /v1/keyboard/profile/reset`)
  - `RollBackKeyboardProfile(caller, idempotency_key, expected_revision, target_revision) -> ProfileResult` (command, `POST /v1/keyboard/profile/rollback`)
  - `DeleteKeyboardProfile(caller, idempotency_key, expected_revision) -> DeleteResult` (command, `DELETE /v1/keyboard/profile`)
  - `ListKeyboardRevisions(caller, limit) -> RevisionPage` (query, `GET /v1/keyboard/profile/revisions`; `limit` 1..20, default 20)
  - `GetKeyboardCatalog(caller) -> CatalogResult` (query, `GET /v1/keyboard/catalog`)
- **PS-109-04.R05** — Idempotency: every command requires `Idempotency-Key` (ULID, 26 chars, generated by the client once per user action). The server stores key, payload hash (SHA-256 of canonical JSON), response and timestamp for 24 hours. Same key and same hash returns the stored response with `"replayed": true`. Same key and different hash returns `KEYBOARD_IDEMPOTENCY_KEY_REUSED`. Queries take no key.
- **PS-109-04.R06** — Event catalog (all `keyboard.event/1`, names versioned by suffix): `KeyboardProfileCreated.v1`, `KeyboardProfileUpdated.v1`, `KeyboardProfileReset.v1`, `KeyboardProfileRolledBack.v1`, `KeyboardProfileDeleted.v1`. Payloads carry `profile_id`, `revision`, `changed_fields` (names only, e.g. `["focus_indicator"]`), `source` and `prior_revision`. Payloads never carry `key_combo` values, action lists or account_id; consumers needing contents call the query.
- **PS-109-04.R07** — Event envelope (CTR-EVT-001): `event_id`, `event_type`, `aggregate_type` = `keyboard_preference_profile`, `aggregate_id` = `profile_id`, `revision`, `actor_ref`, `occurred_at`, `provenance` (`module`, `build`, `source`), `correlation_id`, `idempotency_key`, `schema_version` = `keyboard.event/1`. Signature is omitted: these are relay-issued internal events, not user assertions.
- **PS-109-04.R08** — Schema versioning (CTR-SCH-001): every command body and response carries `schema_version` (`keyboard.profile/1`). Server accepts the current and previous major. Additive optional fields keep the major; clients ignore unknown response fields; servers reject unknown request fields (`KEYBOARD_PATCH_UNKNOWN_FIELD`). A breaking change creates `keyboard.profile/2` with a migration.

## Request and response examples
Update request:
```http
PATCH /v1/keyboard/profile
Idempotency-Key: 01J9Z4M2D7N8P6Q5R3S2T1J0VW
Content-Type: application/json

{"schema_version":"keyboard.profile/1","catalog_version":"kbd-catalog/1","expected_revision":3,
 "patch":{"focus_indicator":"high_contrast",
          "shortcut_bindings":[{"action_id":"focus_search","key_combo":"Alt+S","enabled":true}]}}
```
Success response (200):
```json
{"status":"applied","replayed":false,"event_id":"evt_EXAMPLE_0004",
 "profile":{"profile_id":"01J9Z3K8Q4W6R2T5V7X1Y0ZABC","schema_version":"keyboard.profile/1",
  "catalog_version":"kbd-catalog/1","revision":4,"focus_indicator":"high_contrast",
  "shortcut_hints":"visible_on_focus","shortcut_bindings":[{"action_id":"focus_search","key_combo":"Alt+S","enabled":true}],
  "updated_at":"2026-11-10T08:15:30.412Z","deleted_at":null}}
```
Conflict response (409): `{"code":"KEYBOARD_REVISION_CONFLICT","retryable":true,"current_revision":4,"localization_key":"kbd.error.keyboard_revision_conflict","request_id":"req_EXAMPLE_0002"}`

Query response for a never-saved account (200): `{"profile_id":null,"revision":0,"schema_version":"keyboard.profile/1","catalog_version":"kbd-catalog/1","focus_indicator":"system_default","shortcut_hints":"visible_on_focus","shortcut_bindings":[]}`

```json
{"event_id":"evt_EXAMPLE_0004","event_type":"KeyboardProfileUpdated.v1",
 "aggregate_type":"keyboard_preference_profile","aggregate_id":"01J9Z3K8Q4W6R2T5V7X1Y0ZABC",
 "revision":4,"actor_ref":"acct_ref_EXAMPLE_0001","occurred_at":"2026-11-10T08:15:30.412Z",
 "provenance":{"module":"14_Accessibility/01_a11y/mod_keyboard","build":"build_EXAMPLE","source":"client_web"},
 "correlation_id":"corr_EXAMPLE_0001","idempotency_key":"01J9Z4M2D7N8P6Q5R3S2T1J0VW",
 "schema_version":"keyboard.event/1","payload":{"prior_revision":3,"changed_fields":["focus_indicator","shortcut_bindings"],"source":"client_web"}}
```

## Subscribers
- F15 outbox and audit: all five event types.
- F10: `KeyboardProfileDeleted.v1` schedules tombstone hard delete (30 days, A-KBD-08).
- Observability (PS-109-08): counts only, from event type and outcome.
- No F07 subscription in v1; account deletion is delivered by F07 as its own event and handled by T06 in PS-109-03.

## Open decisions
- A-KBD-01 (ULID identifiers; CTR-ID-001 OPEN), A-KBD-02 (account-scoped profile, no device fields), A-KBD-13 (timeouts), A-KBD-15 (rate limits). Event bus transport is an F15 decision.

## Acceptance criteria
- Every command has a signature, method, path, idempotency rule and error set listed in PS-109-02 R05.
- Every event in R06 has a payload example that contains no key_combo value.
- Contract tests in PS-109-09 cover replay, reuse conflict, and unknown-field rejection.
