## Requirements

- **PS-136-07.R01** Generated data is synthetic and comes only from the shared generators under tests/property/arbitraries; geoprivacy generators deliberately produce raw L4 coordinates and precision-6+ cells as P3 inputs, so a leak of finer precision into a public, search or federated output can fail a property.
- **PS-136-07.R02** Reports contain generated values only for failures, retained 30 days as CI artifacts, and never contain real data.
- **PS-136-07.R03** Seeds are not secret; they are printed in logs and PR comments.

## Specification

**Data classification**
- Generated values: synthetic P0.
- Reports: seeds, paths and shrunk counterexamples.

**Retention**
- Reports and open regression artifacts 30 days as CI artifacts (the issue stays until closed); fixed regression JSON files are kept in git indefinitely.

**Threats and controls**

| ID | Threat | Control |
|---|---|---|
| T01 | Counterexample contains real data pasted by a developer into a regression | regression files are generated by the tool only; lint rejects hand-edited files without the generator signature |
| T02 | Properties silently weakened by lowering numRuns | numRuns floor enforced by the runner (QUALITY_PROP_RUNS_TOO_LOW); the config file is code-owned |
| T03 | Nightly job used to exfiltrate secrets or push code | nightly property job has permissions contents: read and no secrets; only the separate schedule-triggered nightly-report job holds issues: write; no property job holds contents: write or pull-requests: write and no pull request is opened automatically; fork pull requests never run it |

**Abuse controls**
- A property that always passes (no assertion) is caught by a self-test requiring at least one assertion call per property.
- Seeds are never reused to hide a failure: reruns use the printed seed only for replay.
