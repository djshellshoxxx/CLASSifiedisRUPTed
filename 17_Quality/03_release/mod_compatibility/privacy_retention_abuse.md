## Requirements

- **PS-142-07.R01** Fixtures and reports contain no real data; keys are synthetic.
- **PS-142-07.R02** Browser matrix runs use clean profiles with no extensions and no signed-in browser profile; manual checklists record device, OS and browser version but no personal data beyond the approver handle.
- **PS-142-07.R03** Reports are retained 30 days in CI.

## Specification

**Data classification**
- Synthetic fixtures with generated keys (P0/P1).
- Reports: versions, counts, verdicts.

**Retention**
- Fixtures kept in git for the last 2 releases plus the current; reports 30 days as artifacts.

**Threats and controls**

| ID | Threat | Control |
|---|---|---|
| T01 | Fixture keys reused as real keys | fixture keys are generated by the script, marked test-only and rejected by the production key import path |
| T02 | Breaking change sneaks in through a migration | schema diff and N-1 read tests are release-blocking (gates module) and code-owned |
| T03 | Older client acts on a broader promise than was signed because it dropped a restriction the signer added (a new scope, expiry or context binding) | strict payload parsing rejects unknown keys outside ext with VALIDATION_FAILED; ext is preserved byte-exact and capped at 4 KiB; restrictions are listed in ext.crit and an N-1 reader refuses unknown critical keys; unknown major versions refused |

**Abuse controls**
- Changes to fixtures of released versions are rejected: released fixture directories are append-only.
- The browser matrix cannot be reduced without editing the support policy file, which is code-owned.
