# PS-144-04 — commands queries events

**Status:** SPECIFIED — Stage 3 draft, pending review. **Requirement ID:** PS-144-04. **Owner:** [18_Governance/01_policy/mod_goods](SPEC.md). **Implementing module:** 18_Governance/01_policy/mod_goods. **Consumers:** F01 listings (EvaluateGoods, decision events), F12 moderation (referral, decision events), F17 quality (contract tests), F18 reporting (audit events). **Upstream:** F07 identity, F15 platform (CTR-EVT-001, CTR-ERR-001, CTR-SCH-001), F16 security (CTR-CAP-001). See [CONTRACTS](../../../planning/CONTRACTS.md).

## Purpose and scope
**Business outcome.** Other features can evaluate goods, read policy, and react to decisions through versioned, typed interfaces. Every state-changing call is idempotent.

**Exclusions.** Transport choice (HTTP paths, gRPC, queue framing) is an F15 platform decision. Capability checks are in authorization_capabilities.md. Error codes are in validation_rules.md.

## Common request fields
Every command body carries:
- `schema_version` (string, `"1.0"`, A-goods-02).
- `idempotency_key` (string, 16–128 chars, `[A-Za-z0-9_-]`); scope is (actor_ref, command name, key).
- `correlation_id` (string, ULID, optional; generated by the caller if absent).

Every write that depends on current state also carries `expected_version`.

## Events
Every event uses the CTR-EVT-001 envelope: `event_id` (ULID), `event_name`, `aggregate_type`, `aggregate_id`, `revision`, `actor_ref`, `occurred_at`, `correlation_id`, `idempotency_key`, `schema_version`, `provenance` (producing module and version). Payloads carry IDs and enums only; no free text except where marked.

| Event (name.version) | Emitted by | Payload fields | Consumers |
|---|---|---|---|
| goods.category.created.v1 | CreateGoodsCategory | category_id, category_code, status | F01, F17 |
| goods.category.updated.v1 | UpdateGoodsCategory | category_id, status, version | F01 |
| goods.rule.drafted.v1 | DraftGoodsPolicyRule | rule_id, category_id, jurisdiction_scope, policy_class | F18 audit |
| goods.rule.scheduled.v1 | ActivateGoodsPolicyRule | rule_id, effective_from | F18 audit |
| goods.rule.activated.v1 | activation or sweep | rule_id, effective_from, rule_version | F01, F18 audit |
| goods.rule.retired.v1 | Retire or sweep | rule_id, retirement_reason_code | F01, F18 audit |
| goods.decision.recorded.v1 | EvaluateGoods or Decide | decision_id, subject_kind, subject_ref, outcome, reason_code, origin | F01, F18 audit |
| goods.review.opened.v1 | Evaluate with HOLD | case_id, decision_id, sla_due_at | F12 |
| goods.review.escalated.v1 | system at SLA | case_id | F12, F18 audit |
| goods.review.decided.v1 | DecideGoodsReviewCase | case_id, state, reason_code | F01, F13 |
| goods.referral.requested.v1 | Decide with REFER | case_id, subject_ref, category_id | mod_prohibited |

## Schema versioning
- Additive optional fields and new enum values with a documented default are minor changes within `1.x`. Consumers ignore unknown fields.
- Removing or renaming a field, or changing a type, is a major change: new path `/v2` and event `.v2`. Both versions are served for at least 6 months (A-goods-02).
- Unsupported `schema_version` returns GOODS_SCHEMA_VERSION_UNSUPPORTED.

## Assumptions
- Assumptions for identifiers and schema version are defined in domain_schema.md (A-goods-01, A-goods-02). Transport is not decided here.
