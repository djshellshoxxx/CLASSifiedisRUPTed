## Implemented bounded product slice
- `verifySealedAttachmentBlobBatch(sealed, passphrase, expectedPrincipal, byteSet)` authenticates the existing signed and encrypted `classrup.vault.attachment_manifest/v1` manifest, requiring trusted principal match and its complete metadata/ownership statement.
- Batch entries must correspond exactly to the manifest's sorted `blobs` list. A bounded indexed snapshot copies exact stored byte lengths; SHA-256 content-address verification then checks **all** members. Reject missing, extra, reordered, size-mismatched or changed bytes with no accepted prefix. Do not use a caller-supplied array iterator; copied temporary bytes are cleared on success and failure. Returned value is verified metadata, never plaintext bytes.
- The existing constraints (32 items, 5 MiB per blob, 20 MiB aggregate) remain unchanged; this implementation does not modify v1 backup wire, identities, signatures, KDF/encryption policy, codec registry or test timeouts.
- This verifies a batch **passed into the API**, not a secure external transport protocol. Caller must separately perform the destination record owner reconciliation and a fresh owner recheck within an eventual atomic destination write. No import, re-encryption, rollback, encrypted destination reopen, permissions delegation or full attachment recovery is claimed.
