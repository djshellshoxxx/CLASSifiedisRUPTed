## Proposed next durable implementation contract (not implemented)
Read-only v1 evidence is deliberately insufficient for mutation authorization. Do not reinterpret a revision, matching data CID, timestamp, absent parent, or zero-reference snapshot as an authenticated canonical mutation. Existing v1 archive bytes and signatures must remain unchanged.

1. Define durable tenant/type/key-scoped incarnation identity and lifecycle journal at the canonical mutation boundary, not a caller-supplied ID and not a side effect of snapshot export. Choose a separately versioned authenticated local store/codec with bounded retention and documented encrypted backup inclusion policy; explicitly deny legacy/no-lineage records mutation-authority status until a real authorized transition can be recorded. Ensure create, update, delete, restore, and rollback semantics are specified; a recreation must not reuse an old incarnation. No global identity changes.
2. Add a separately versioned transition record emitted as part of an authorized canonical update/deletion, binding trusted principal, exact canonical key, incarnation, before/after revision and content CIDs, affected refs, and a stable transition identifier. Missing parent alone is not proof. Preserve read-only v1 issuer/verifier as compatibility paths.
3. Atomic non-final retirement: verify transition and owner scope, check current incarnation and exact revision within destination transaction, reconcile current canonical holders before detachment, and store consumed transition state in the same durable unit of work as holder changes. Duplicate delivery may return an explicit idempotent result only when the same consumed transition matches; stale or unrecognized evidence fails closed. Never delete final-held bytes or request key shredding until a distinct retention/key contract exists.
4. Add normal lifecycle acceptance in memory and encrypted IndexedDB: update/restore/reopen preserves lineage, delete/recreate creates new lineage, restored legacy v1 data remains readable, late persistence failure rolls back transition state and holder indexes together, duplicate delivery is idempotent, canonical current holders retained. Bound the journal and define how recovery/rollback of old archives affects authority before admitting cross-device replay. A local consumed marker alone does not establish cross-device replay protection.
5. Production PWA media integration and private destination-key transport are separately gated. No destructive feature activation until these contracts and independent review are complete.
