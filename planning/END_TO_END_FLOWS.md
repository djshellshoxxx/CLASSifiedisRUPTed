# End-to-end acceptance flows
Status: PROPOSED test scenarios, NOT executed. Each step should become a linked integration/e2e test in F17. Depends on CORE_API_EVENTS_DATA.md, CLASSIFIED_LISTING_CONTRACT.md, CYCLE_BARTER_EXECUTION.md and MESSAGING_PAYMENTS_FEDERATION.md.
All examples presume same tenant and consenting legal-age parties; no physical handoff guaranteed by software.

| ID | Journey | Ordered flow | Failure / acceptance oracle |
|---|---|---|---|
| FLOW-01 | Paid classified placement | seller creates draft -> listing category validation -> moderation approval -> promotion quote -> external processor payment request -> payment.claimed from user redirect -> independent provider confirmation -> promotion activation idempotent -> public promoted label -> expiry | redirect alone NEVER grants placement; double provider callback grants one placement; rejected listing no promotion and refund/appeal flow |

| FLOW-03 | Two-party barter | A offers item a to B for b -> 2-cycle matcher finds A->B->A -> digest computed -> A and B accept same digest -> source items CAS reserved -> handoff -> each asserts own side -> reported completion | offer edit invalidates both accepts; one dropout creates case and releases unused locks only |
| FLOW-04 | Three-party cycle | A wants C's item, B wants A's, C wants B's -> A->B->C->A -> validate uniqueness/conditions -> consent A/B/C -> lock all -> manual transfers with recipient acknowledgement -> case closure | missing C acceptance prevents lock; no automatic transfer after first handoff |
| FLOW-05 | Four-party cycle | A->B->C->D->A -> four commitments + one shared digest -> lock only after all four approvals -> coordinate independent handoffs | stale inventory of D causes whole proposal lock to fail, none of other three reservations persist |

| FLOW-08 | Cancellation and dispute | B revokes before lock -> invalidated consents -> all reservations released; alternatively B drops out after receiving item -> freeze plan -> append case evidence -> resolution options and user notification | no silent reroute/rewrite or deletion of existing evidence; only agreed new proposal may replace |

## Common quality checks
For each flow: verify authorization, tenant and block status before any mutation; 24-hour request idempotency; retry after timeout; stale If-Match; unavailable external service; offline stale UI; voiceover/NVDA keyboard path; localized currency value unchanged; provenance of every event; no exact location in public/export/log; consistent notifications and eventual projector updates. Before a flow passes, attach test file, fixture ID, CI run and reviewer to registry cross-reference. A textual narrative alone is not proof of completion.
