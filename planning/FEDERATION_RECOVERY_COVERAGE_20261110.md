## Authorities and non-negotiable trust boundaries

- [ADR-0016](adr/ADR-0016.md) (owner accepted): the vault is authoritative; local user-held keys; relay participation is optional and user-selected. No relay can create consent, decrypt participant data, or guarantee atomic physical exchange. Signed receipts only evidence that relay's assertions.
- [ADR-0013](adr/ADR-0013.md) (amended by ADR-0016): device linking, key rotation/revocation, one-time recovery kit and recovery controls remain distinct from merely recovering one signing key.
- [CTR-FED-001](contracts/CTR-FED-001.md): signed canonical cross-party statements, author ordering, provenance, tombstone lifecycle and allowlisted relay-to-relay transport.
- [CTR-IOX-001](contracts/CTR-IOX-001.md): complete signed user export, validation/dry-run before import, rollback, user-selected backup and relay-only operational backup.
- [CTR-PRV-001](contracts/CTR-PRV-001.md): P0 opt-in federation; P2 ciphertext only for participants; P3/P4 vault-only except owner export. The key-encrypted vault is **not** a record-encrypted vault today.

This matrix **does not** approve a new envelope format, KDF, device recovery protocol, retention exception, or relay authority. An implementation affecting those must follow its approved owner/ADR process.
