# ADR-0016 — Local-first hybrid architecture (supersedes relay authority in ADR-0001/0002)

**Status:** ACCEPTED by the repository owner on 2026-11-04. **Supersedes:** the relay-as-authority parts of ADR-0001, ADR-0002 and ADR-0013. Reconciles main with the client-owned constraint recorded in open PR #2 (`planning/CLIENT_SIDE_ARCHITECTURE.md` on `docs/client-owned-foundations-20261024`).

## Decision
1. **The installable PWA is the product.** Every domain module runs in the browser against the user's local **vault** (IndexedDB, one per principal). Drafting, listing, local search over retained records, matching, proposal review, evidence review, export and restore work with no server.
2. **Identity is a user-held key** (Ed25519 device keys, did:key principal). There is no central account database, no product-operated credential issuer and no server-held user secret. A pseudonym is a display label; uniqueness exists only within a relay that chooses to register handles.
3. **Relays are optional, self-hostable, user-selected adapters** running the same modular packages (`apps/relay`). A relay may: index signed public projections for discovery, store-and-forward end-to-end encrypted envelopes (mailboxes), run matching over public projections, send content-free Web Push, host auctions whose seller and bidders explicitly select it, and federate with other relays. A relay is **never** authoritative for a user's private records, never sees plaintext private messages, keys, exact addresses or private graphs, and cannot change a user's records. Stopping a relay leaves every local record intact and makes delivery status *unknown/pending*.
4. **All cross-party state is signed statements.** Anything another party must rely on (published listing, offer, acceptance, proposal revision, consent, reservation, handover/receipt attestation, review, tombstone) is a CTR-FED-001-style signed envelope over RFC 8785 JCS bytes. Each receiving vault verifies signatures and keeps provenance. Relays relay; vaults decide.
5. **Consistency limits are explicit (no false guarantees).** A local reservation only prevents conflicts within that vault. Cross-vault cycles collect unanimous signatures on an immutable proposal digest; there is no distributed lock or atomic physical exchange. Conflicting signed promises from forked vaults are detected and freeze the affected coordination for explicit renegotiation; no last-writer-wins for consent, money, identity revocation or inventory commitments. Timestamps from other parties are claims; a relay-signed receipt time is evidence only of that relay's clock.
6. **Features that need an ordering authority require an explicitly chosen host.** Auctions (close time, bid order) run only on a host relay chosen by the seller and accepted by each bidder at bid time; the UI names the host and its trust. Without a host the auction feature is disabled (fail closed). Paid promotion is a relay-local policy of the relay that indexes the listing.
7. **Authorization has two layers.** (a) Vault policy: only the local principal may mutate its records; incoming statements are accepted only if signed by an authorized key for that role (e.g. only the listing author may accept an offer on it). (b) Relay policy: a relay authorizes access to its own resources (index writes, mailbox reads, auction hosting) using signed requests or challenge-response relay access tokens; relay roles (moderator, operator) govern only what that relay hosts.
8. **Moderation is local filtering plus relay hosting policy.** Users hide/block locally and may subscribe to signed advisory feeds; a relay operator can refuse or remove content from that relay's index with a statement of reasons. No global takedown or global suspension is claimed.

## Code consequences
- `packages/kernel` core is isomorphic (no `node:` imports); adapters live behind ports: `storage/indexeddb` (browser vault), `storage/sqlite` and `http` (relay, Node-only subpath `@classrup/kernel/node`), `storage/memory` (tests).
- The command bus runs in both environments: in the vault it dispatches locally (actor = unlocked local principal); in the relay it serves relay commands over HTTP.
- Every module spec distinguishes **vault commands** (local, authored by the principal), **statements** (signed envelopes exchanged with others), and **relay commands** (optional relay services).

## Consequences for contracts
CTR-CAP-001, CTR-EVT-001, CTR-IDM-001, CTR-IOX-001, CTR-OBS-001 and CTR-PRV-001 carry ADR-0016 amendments. ADR-0013 recovery: the recovery kit stays with the user (download/print); upload only to a user-selected encrypted backup location; never to a relay by default.
