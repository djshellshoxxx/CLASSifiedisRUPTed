# Client-owned listings, sale and placement contract
Status: **SPECIFIED_REVIEW_PENDING**. Owners F01 listings, F06 local search, F09 evidence, F12 local moderation. Inherits [core](CORE_API_EVENTS_DATA.md). CL-001..007 retained with revised local semantics; no implementation/test approval.

## Fields (CL-001)
Owned listing `{id,owner_principal_id,kind:sell|wanted|giveaway,title?,description,condition:new|used|for_parts|unspecified,public_area_id?,price:{currency,amount_minor}|null,price_on_request:boolean,quantity,state:draft|pending_local_review|published|reserved_local|closed|archived|hidden_local,visibility:private|unlisted|public,revision,economic_revision,economic_digest?,expires_at?,created_at,updated_at}`. Core types apply. Title if present 3..120 code points; description <=10000; area code 3..64 from pinned local catalog. Draft defaults: empty description, unspecified condition, quantity 1, null price, price_on_request false; title/area may be absent. Publish requires title/area and sell price positive <=9e15 minor units or explicit price_on_request; wanted/giveaway forbid price and price_on_request. Quantity integer 1..100000 for open listings, 0 allowed only closed/archive. Public fields cannot carry contact/address/coordinates; free text receives disclosure warning.
IndexedDB objects contain local identity references, no tenant/account FK. Attachment refs are local validated media IDs, never arbitrary active URLs; strip metadata before public export. Local hold `{listing_id,unit,proposal_id,proposal_digest,expires_at,state}` has one active entry per unit in this vault. This prevents only this vault's double allocation. Peer imports are separate signed projections, never authoritative owned listings.

## States (CL-002)
`draft -> pending_local_review -> published -> reserved_local -> closed`; draft/published/pending_local_review may archive; reserved_local may release to published with explicit cancellation evidence. Local filter hide does not delete foreign data. Published means locally approved public projection eligible for explicit export; it does not mean peer delivery/indexing. All transitions CAS expected local revision and atomically record receipt/event/hold changes. `reserved_local` is a local availability overlay: creating/releasing a hold increments local revision only and preserves signed economic_revision/digest referenced by the proposal. Material listing edits, public lifecycle/availability withdrawal and terms changes advance economic_revision and invalidate prior consent; reject such edits while a hold exists unless explicitly canceling that proposal and releasing the hold in the same local transaction. Imported signed record revision is economic_revision; local filtering/delivery bookkeeping cannot masquerade as a new signed terms record. Expiry uses advisory local clock; clock anomalies pause automatic expiry and surface review. Re-publish creates new revision and policy review. Closing reports owner's assertion; no payment/handover guarantee.

## Commands (CL-003)
In-process `listing.create(input)`, `listing.edit(id,expected_revision,patch)`, `listing.publish`, `listing.archive`, `listing.reserveLocal(proposal_digest,units,expires_at)`, `listing.releaseLocal(matching_hold)` use CR-002 context/command envelope. Create returns private draft local revision 1/economic_revision 1 plus local committed receipt; economic_digest is absent until a reviewed signing profile exists. Query `listing.getOwn(id)` requires unlocked owning vault; `listing.searchLocal(filter,cursor)` excludes private drafts and quarantined/hidden/expired projections. Cursor references local snapshot generation, filters/sort and position; after generation change return CURSOR_STALE and restart, never global sequence. Page <=100, search input <=200 code points.
Reject ownership/state/revision input on create. Errors include VALIDATION_FAILED with bounded field paths, REVISION_CONFLICT, RESOURCE_RESERVED_LOCAL, POLICY_UNAVAILABLE, FEATURE_DISABLED and PROTOCOL_NOT_REVIEWED. All commands inherit durable idempotency. Unlocked owning principal and local policy are rechecked inside transaction. No backend/session assumed.

## Optional placement (CL-004)
No mandatory product-operated paid placement/payments backend. Local placements are explicit user-selected display rules with disclosure; a remote publisher may offer a separate optional service. Placement record `{placement_id,listing_id,publisher_id,terms_digest,window,payment_claim_id?,evidence_ids,status:proposed|awaiting_evidence|publisher_acknowledged|expired|disputed}` describes local knowledge only. A browser redirect or receipt cannot grant global placement. User-selected publisher/payment verifier may supply evidence; UI identifies its source and limits. Absent separately reviewed publisher/payment protocol, paid placement activation is disabled. External services may have their own refund terms; no product guarantee of availability/refund.

## Ordinary local sale (CL-005)
Discover locally cached public listing -> agree immutable proposal digest and disclosures through reviewed optional transport or off-app contact -> each party records its own consent -> seller optionally creates local hold -> pay directly off-platform -> record separate payer/payee assertions and optional external source evidence -> each party attests handover -> owner closes as reported completed. In-app messaging is disabled pending MPF-001 review. No assertion is fabricated for another participant. Missing/conflicting evidence stays unknown/disputed; signature is key authorship, cash is never cryptographically verified. A seller can publish conflicting records from another vault; detection quarantines known forks, no global exclusivity promise.

## Privacy and usability (CL-006)
Local search immediately excludes archive/hide/delete in the same projection transaction; disconnected peers may retain old copies indefinitely. Explicit public export consent selects fields/destinations, warns about redistribution, and excludes drafts. User owns retention/backups; no product account sanctions or global takedown clock. Locally selected advisory feeds may inform review but cannot assert universal legality/trust. Local quotas protect device resources, not Sybil resistance. Manual coarse area works without geolocation. Keyboard error summary, status announcements and explicit promoted-content labels required. Media policy/profile review blocks attachment sharing until approved.

## Tests and acceptance (CL-007)
T-CL-01 two tabs in one vault reserve last unit: one local commit, economic revision/digest and existing consent unchanged by that hold; material edit requires cancellation/new consent; independent vaults may both reserve and UI explains scope. T-CL-02 forged owner/key and payment redirect create neither owned listing nor placement. T-CL-03 local archive/remove immediately excludes local index; stale peer copy remains labeled. T-CL-04 Unicode/control/unknown field and money boundaries reject typed errors. T-CL-05 dropped local result/reload replays identical receipt with one object/event. T-CL-06 denied geo permission retains manual coarse region. T-CL-07 keyboard create/publish and disabled payment/messaging explanations announce status. All seven are specified, not executed; acceptance needs browser evidence, independent security/privacy/protocol review and local policy decisions. These IDs replace prior server/global expectations explicitly.
