# Listings, direct sale and paid placement contract (proposed)
Owners F01 listing modules; F06 search; F09 payment evidence; F12 moderation. Inherits CORE_API_EVENTS_DATA.md, superseded only by versioned ADR. Status: detailed integration baseline, not yet translated into all module process files.

## Fields (CL-001)
listing {id:uuid,tenant_id:uuid,owner_id:uuid,kind:enum(sell,wanted,giveaway),title:string(3..120),description:string(0..10000),condition:enum(new,used,for_parts,unspecified),public_area_id:string(3..64),price_currency:char(3)|null,price_minor:bigint|null,quantity:int[0..100000],state:enum(draft,pending_moderation,published,reserved,closed,archived,removed),visibility:enum(public,unlisted,private),revision:int64>=1,expires_at:timestamptz|null,created_at,updated_at}. For sell listing quantity >=1 until closed; wanted and giveaway price must be absent; paid promotion is independent from sale price. Reject sale price null for sell unless listed as price_on_request=true (default false); this flag must be explicit in full module contract.
SQL constraints: CHECK(quantity>=0), CHECK(revision>=1), CHECK(visibility IN (...)), UNIQUE(tenant_id,id); owner FK includes tenant ID; CHECK(kind<>'giveaway' OR price_minor IS NULL); constrain enum and exponent in application with versioned rule set.
Draft may lack title/area; publish MUST meet full schema. Attachment image metadata F08/F15, never unrestricted raw URLs. Inventory reservation row {listing_id,token,proposal_id,expires_at,state} unique active exclusivity via guarded transaction, not nullable global token.
Publication promotion {placement_id,listing_id,requester_id,currency,amount_minor,starts_at,ends_at,payment_claim_id,verification_id,status}; no promotion awarded merely on payment claim; if verification unavailable, keep pending and offer retry/refund instructions according to processor. Paid classification listings are not identical to the item's sale price.

## States (CL-002)
draft -> pending_moderation -> published -> reserved -> closed; draft/published/pending_moderation -> archived; published/reserved -> removed by moderation; reserved -> published on consent-safe cancellation/release. Expiry published -> archived; background expire is CAS with revision; expiry does not close settled proof. Re-publish after archive creates new revision and re-checks policy and inventory. Concurrent reserve permitted to exactly one exclusive proposal per item quantity unit; conflicting reserve returns 409 RESOURCE_RESERVED, never double allocates.

## Commands (CL-003)
POST /api/v1/listings -> draft; PATCH /api/v1/listings/{id} with If-Match revision -> new draft/published revision; POST /api/v1/listings/{id}:publish -> moderation gate; POST :archive; POST :reserve for agreed proposals; POST :release requires matching reservation token or approved operator case. GET /api/v1/listings/{id} public only when published+visible; GET /api/v1/my/listings owner. All mutations idempotent 24h; pagination opaque cursor bound to filters/sort/tenant and expiring after 15m. No unauthenticated writes.
Validation: title NFC 3..120, prohibited HTML markup escaped; unit price >0 for sell with a fixed price, <=9e15 minor, ISO currency; area must be approved coarse area not arbitrary coordinates; forbidden regulated/prohibited category decisions by F18. Invalid fields 422 path code; stale revision 409 REVISION_CONFLICT; disabled feature 403 FEATURE_DISABLED; moderator hold 423 RESOURCE_LOCKED; missing image blocked only if listing policy explicitly requires it.

## Paid listing flow (CL-004)
Create draft -> validation -> moderation -> choose promotion product -> quoted promotion amount -> external payment redirect or customer wallet handoff -> payment.claimed records assertion (no effect) -> provider-verified paid state or manually verified cash policy -> grant placement for purchased window using idempotent promotion_activation_id -> publish searchable promoted entry with disclosure flag. Promo availability rechecked at activation; if expired or rejected apply refund policy, never auto-mark settled on browser redirect.

## Ordinary local sale (CL-005)
Buyer discovers public listing -> sends private inquiry -> seller offers price/terms -> both accept immutable proposal revision -> optionally reserve inventory -> buyer pays directly off-platform or at meetup -> separate receipt assertions -> independently confirmed payment if supported -> both attest handover -> close as 'reported completed' with explicit reliability labels. A false or absent attestation leaves outcome disputed/unknown, not confirmed by platform. Cash never 'cryptographically verified'.

## Nonfunctional (CL-006)
Moderation before public indexing; takedown search invalidation <=60s P99 under one regional healthy instance; import never bypasses moderation. User-friendly keyboard error summaries; labels for promoted content; screenreader announces pending, failed, stale. Cache public results max 60s; authenticated draft no shared cache. Export excludes other users' data. Owner public pseudonym only; precise meetup details never indexed. Fraud: report button, posting quotas, velocity checks, blocklist, ban evasion signals minimized, prohibited category filter and appeal path.

## Tests/acceptance (CL-007)
T-CL-01 two clients simultaneously reserve last unit: exactly one commit; second 409. T-CL-02 forge owner/tenant/paid redirect: deny, no promotion. T-CL-03 archived/removed listings absent from public search within 60 seconds. T-CL-04 malformed Unicode/control/unknown fields rejected as enumerated. T-CL-05 network drop after successful POST returns cached identical receipt on retry. T-CL-06 no geolocation permission retains manual coarse region. T-CL-07 keyboard-only create/pay/publish with status annunciation. Acceptance requires all 7 tests automated plus moderation/jurisdiction policy sign-off; not executed.
