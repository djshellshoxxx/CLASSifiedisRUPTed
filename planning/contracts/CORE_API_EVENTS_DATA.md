# Client-owned command, data, event and permission contracts
Status: **SPECIFIED_REVIEW_PENDING**. contract-v2-local, 2026-10-24. Proposed interfaces only; no implementation, security approval or passing test evidence.
Owners: F15 local persistence, F07 local identity, F16 authorization, F10 privacy. Applies to the entire CLASS suite. This baseline replaces product-operated HTTP/SQL/account assumptions in contract-v1; CR-001..006 remain traceability IDs with revised client-owned semantics. Downstream incompatible text cannot authorize a backend dependency.

## Canonical types and trust boundary (CR-001)
Every user controls a local vault, its data, principal keys and export destinations. No required product API, SQL service, account store, cookie session or product-held user secret. Optional user-selected peers, relays and storage are untrusted transports, never authorities over local records. A browser origin may serve static application assets; it is not a user data service.
IDs are client-generated UUIDv4 lowercase canonical strings from a platform cryptographic random source; they are opaque, not time/order/identity evidence. A vault ID identifies local storage, not a tenant or globally unique person. Principal ID refers to a vault's selected public-key identity; one human can have several identities. Imported records retain origin principal/object IDs in a separate projection namespace. UUID collisions in a vault are rejected and regenerated before first commit, never overwrite an existing object.
Revision is integer 1..9007199254740991, scoped to one object's local storage history. For listings, `revision` is local CAS bookkeeping while `economic_revision` and `economic_digest` identify immutable owner-signed terms. Only material terms/availability/public lifecycle changes advance economic_revision and invalidate dependent proposal consent; local holds, delivery metadata and local filtering advance only local revision. Signed listing/federation record revision refers to economic_revision, never local CAS revision. Timestamps are RFC3339 UTC milliseconds from the client clock, advisory only. No global time, sequence or freshness authority; clock rollback requires a visible warning and explicit handling of deadlines. Money is ISO4217 currency plus canonical decimal-string integer minor units, magnitude <=9000000000000000, using arbitrary precision arithmetic and a release-pinned exponent table. Domain rules forbid negative values where specified.
Text is NFC; limits count Unicode code points after normalization. Reject NUL and unsupported controls; tab/newline permitted only for multiline fields. Escape rendering. Public geo is a manually selectable coarse catalog area; no public precise location/contact fields. Free text can disclose personal data: warn before sharing; automatic detection cannot guarantee removal.
Cryptographic interoperability is a **protocol-design review blocker**, not product implementation permission. Canonical encoding, digest/signature algorithms, domain separation, key IDs, discovery, verification, rotation, recovery and test vectors require one versioned reviewed profile. No home-designed cryptography or security/E2EE claim. Until reviewed, drafts/local workflows remain available; signing, peer import/export and messaging send/receive remain disabled. Local message drafts are allowed in memory only pending reviewed protected storage; they have no delivery or consent meaning. Persistent sensitive data requires a separately reviewed storage/key protection design; otherwise keep it memory-only or refuse persistence.

## Local interface and errors (CR-002)
Canonical interface is a typed in-process call, not a mandatory network endpoint:
`execute({vault_id, principal_id, command_id, operation, expected_revision?, input}) -> Result<Receipt, Problem>`; `query({vault_id, principal_id, query, filter, cursor?}) -> Result<Page, Problem>`.
Principal/key handles come from the unlocked vault context, never caller-supplied ownership claims. Local authorization is rechecked in the write transaction. JSON-compatible command input <=256 KiB UTF-8, unknown fields rejected; attachment ingestion is separate. Locked/unavailable vault fails closed. Public projections may be read from an explicitly selected local cache with provenance/staleness labels.
Receipt `{command_id, object_id, revision, local_status:"committed", event_ids, committed_at}` proves a local transaction completed. Before transaction completion UI says `local_pending`; peer transport acknowledgments, participant consent and external settlement are separate records, never inferred from this receipt. `queryCommand(command_id)` resolves interrupted calls; absence after confirmed transaction abort permits retry, not automatic success.
Problem `{code, request_id, field_errors:[{path,code}], retryable, retry_after_ms?}`; no HTTP status dependency. Codes: MALFORMED_INPUT, PAYLOAD_TOO_LARGE, VALIDATION_FAILED, VAULT_LOCKED, FORBIDDEN, FEATURE_DISABLED, REVISION_CONFLICT, IDEMPOTENCY_MISMATCH, RESOURCE_RESERVED_LOCAL, NOT_FOUND, EXPIRED_LOCAL, POLICY_UNAVAILABLE, STORAGE_UNAVAILABLE, STORAGE_QUOTA_EXCEEDED, RATE_LIMITED_LOCAL, PROTOCOL_NOT_REVIEWED, CONFLICT_QUARANTINED, CURSOR_STALE, DEPENDENCY_UNAVAILABLE, OBJECT_DELETED, PROFILE_UNSUPPORTED. Hidden objects use NOT_FOUND without existence disclosure. Peer adapters map transport failures separately and cannot change local outcome.
Idempotency scope `(vault_id, principal_id, operation, command_id)`: immutable canonical request bytes and original result. Same bytes return original receipt; changed bytes return IDEMPOTENCY_MISMATCH. Valid committed command IDs/receipts remain for object lifetime, plus a deletion anti-replay marker; explicit destructive vault reset abandons that guarantee. Resolve existing receipts/anti-replay markers before charging create quotas; identical replay is not a fresh create attempt. On object deletion, atomically scrub canonical request bodies, private historical snapshots and content-bearing events/outbox payloads, then retain only command scope/ID, object ID and deletion marker, with no request fingerprint/digest. Any replay/query under that deleted command scope/ID returns OBJECT_DELETED without payload comparison or original body/receipt content and cannot recreate it. Changed-body replay of a deleted command also returns OBJECT_DELETED; IDEMPOTENCY_MISMATCH applies to live receipts only. This avoids retaining guessable private-text hashes. Marker metadata still exposes correlation and retention must be disclosed; explicit marker erasure sacrifices replay protection. Prevalidation errors need not be recorded. Never silently retry a new ID when an old outcome is unknown. Canonical byte encoding also awaits the reviewed profile; no implementation hash substitute is approved here.

## Events and delivery (CR-003)
State, receipt and local event/outbox entry commit in one IndexedDB readwrite transaction. Event `{event_id, event_type, event_version:1, vault_id, principal_id, aggregate_id, aggregate_revision, occurred_at, correlation_id, causation_id, payload}` contains minimal local references; never plaintext messages, keys, precise locations or payment credentials. Vault/principal correlation metadata must not be copied wholesale to public transport.
Canonical event names are exact, not slash-expanded aliases:

| Names (event_version 1) | Meaning / payload refs |
|---|---|
| listing.created, listing.updated, listing.published, listing.archived | Local lifecycle; listing_id, economic_revision where applicable |
| principal.deletion_requested | Local principal deletion intent; principal reference only; no remote-erasure authority |
| reservation.created, reservation.released | This vault hold only; listing_id, proposal_digest, hold_id |
| offer.proposed, offer.countered | Proposal revision locally recorded; offer_id, proposal_digest |
| cycle.proposed, cycle.consent_recorded, cycle.locked, cycle.cancelled | Local cycle/evidence changes; cycle_id, proposal_digest; locked means local hold only |
| handoff.attested, dispute.opened | Named party assertion/case reference; subject_id, evidence_id |
| payment.claimed | Participant claim; claim_id, proposal_digest |
| payment.observed | Source-labeled observation/source confirmation; claim_id, evidence_id, source_id, evidence_status; never settlement finality |
| payment.verification_revoked | Previously accepted source evidence revoked; claim_id, evidence_id, reason_code |
| moderation.local_hidden | Local projection hidden; object_ref, local_policy_version; no global takedown |
| message.sent | Reserved; cannot fire until messaging protocol approved |
| federation.record_imported | Validated local projection, not owned authority; origin ref, record_id |

Historical `payment.verified` maps to `payment.observed`; `moderation.actioned` maps to `moderation.local_hidden` only for local hiding (other actions require a separately specified event). Neither historical alias may be emitted. No implementation exists to dual-emit/migrate; future imported historical events require explicit schema migration/quarantine. Payloads contain refs only, not private evidence/content. Old names confer no global guarantees; breaking implemented meanings require a versioned migration.
Local consumers deduplicate `(consumer_id,event_id)` within their own atomic projection transaction. Outbox is at-least-once work, not exactly-once network delivery. Peer ACK only records that peer's assertion of receipt; expiry/retry/dead-letter cannot mark remote consent, publication everywhere or settlement. Local events are private; outbound public records are separately allowlisted, explicitly consented and signed after protocol approval.

## IndexedDB reference layout and atomicity (CR-004)
One database per local principal/origin vault, versioned schema. Stores: `objects` key `[type,id]` with revision/owner/state; `commands` key `[principal_id,operation,command_id]` with canonical request and receipt; `events` key event_id; `outbox` key `[destination_id,event_id]` with attempts/next_attempt/status; `inbox` key `[origin_principal_id,origin_object_id,revision,digest]`; `projections` key `[origin_principal_id,type,id]`; `conflicts` key conflict_id; `local_holds` key `[listing_id,unit]`; `consumer_receipts` key `[consumer_id,event_id]`; `key_metadata` holds public metadata and opaque local protected handles only. Detailed secret persistence remains review-blocked.
Each mutation opens one readwrite transaction covering all touched stores, checks revision, local policy and hold occupancy, then writes all or aborts all. Multi-tab races use IndexedDB transaction serialization and re-read guards; BroadcastChannel/UI locks are advisory only. No awaited network or signing work inside the transaction: precompute signed bytes outside, recheck exact revision/digest/policy when committing. No signing operation until approved profile exists. Transaction completion gives browser-local atomic commit, not protection against OS failure, eviction, compromised device or rollback of a backup. Request persistent storage where available; show backup/eviction risk honestly.
Exact duplicate imported digest is a no-op. Unknown keys, missing predecessor history, unsupported schema and locally revoked keys quarantine without indexing until explicit reviewed trust/history reconciliation. Distinct valid signed records with same origin/object/revision go to conflicts; quarantine the object, stop indexing/action and require explicit resolution with provenance and new authorization. Never choose latest arrival, timestamp, lexicographic digest or higher peer reputation as silent winner. Higher revision alone does not repair a quarantined fork. Imported records never overwrite owned records or create consent/holds on another vault.

## Local capabilities and key lifecycle (CR-005)
Default deny. An unlocked per-vault principal can create/edit its own records; a named participant may sign only its own proposal consent; imported public records have read/projection permission only. No global member/moderator/operator roles or bans. User-selected local filters and signed advisory moderation feeds can hide records locally; they cannot revoke foreign ownership or erase peer copies. Selected trust policy failure blocks affected sharing/import actions, not unrelated local drafting.
Delegation is disabled until scoped, bounded capabilities and revocation behavior are reviewed. Key signatures prove key authorship only, not human identity, asset ownership/truth, consent beyond signed scope or global exclusivity. Rotation/revocation must bind old/new identity and scope under the reviewed profile; locally trusted revocations block subsequent local acceptance, but offline peers may miss them. Lost keys have no product recovery escrow. Backup restoration must not silently reactivate revoked keys or resend old exports; unresolved history is quarantined pending reconciliation.

## Retention, outage and telemetry (CR-006)
User chooses local retention/export/erase. Default draft remains until explicit deletion; optional local diagnostic ring is off by default, redacted and capped at 1000 entries/7 days. Receipts/anti-replay markers retained as CR-002; tombstone/conflict metadata exposes correlation and needs disclosed retention controls. Deleting those markers explicitly sacrifices replay protection. No central legal hold or global erasure promise. Peer copies, backups and external recipients may survive local deletion.
Offline local commit is valid without a server. Disconnected peers remain unknown/stale; no background worker guaranteed while browser closed. Visible states distinguish local pending/committed, queued/peer acknowledged, consent missing/recorded and settlement claimed/source-observed. Proposed local budgets: p95 create <=200ms and p99 <=1000ms over 10,000 drafts and 100 serialized creates on a declared reference device; independent tabs additionally test races. Unmeasured targets, not service SLOs. Storage/policy/crypto failures produce typed errors; diagnostics never upload automatically. Acceptance requires real-browser transaction/crash/eviction/restore tests, peer-fork adversarial fixtures and independent protocol/security review before sharing features.
