# CTR-ID-001 — Identifiers, revisions and schema names

**Status:** APPROVED. **Owner:** F15.S02.M02 (mod_api).

## Rules
- **ID-1** Every persisted record has `id`: UUIDv7 (RFC 9562 §5.7), lowercase canonical 8-4-4-4-12 form, generated by the writer (client or relay). Relays reject IDs whose embedded timestamp is more than 24 h in the future (`ID_TIMESTAMP_SKEW`, 422).
- **ID-2** Branded TypeScript type `Id<'Entity'>`; IDs of different entity kinds are never interchangeable.
- **ID-3** Federated or signed content additionally carries `cid`: `sha256-` + base64url(SHA-256(JCS(payload))) (RFC 8785 canonical JSON). `cid` is used for deduplication, never as a database primary key.
- **ID-4** `revision`: integer, starts at 1, incremented by exactly 1 on each accepted state change. Optimistic concurrency uses `expectedRevision` (see CTR-IDM-001).
- **ID-5** Schema name: `classrup.<featureSlug>.<entity>/v<major>`; examples `classrup.bazaar.listing/v1`, `classrup.mutiny.cycle/v1`. Feature slugs: bazaar, mutiny, services, auctions, rentals, discovery, identity, comms, commerce, privacy, federation, moderation, notify, i18n, platform, security, quality, governance.
- **ID-6** Tenant: every record carries `tenantId` (UUIDv7). A single-tenant deployment uses one fixed tenant created at bootstrap.
- **ID-7** Timestamps are RFC 3339 UTC strings with millisecond precision (`2026-11-04T10:15:30.123Z`). Durations are integer milliseconds or ISO 8601 durations in configuration only.

## Base record shape
```json
{ "id": "0192f3a4-5b6c-7d8e-9f01-23456789abcd", "tenantId": "…", "schema": "classrup.bazaar.listing/v1",
  "revision": 3, "createdAt": "2026-11-04T10:15:30.123Z", "updatedAt": "2026-11-04T11:00:00.000Z",
  "createdBy": "<actorId>" }
```
## Tests
Property: generated IDs are unique (1e6 sample) and monotonic per generator within a millisecond (RFC 9562 §6.2 method 1 counter). Contract: parser rejects uppercase, braces, v4 IDs where v7 required.
