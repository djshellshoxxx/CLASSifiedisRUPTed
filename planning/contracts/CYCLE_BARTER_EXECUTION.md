# LocalMutiny matching, consent, value and execution contracts
Status: PROPOSED architecture baseline; not implementation, testing or security approval. Owns F02 contracts; F01 owns source inventory, F07 authorizes identity, F09 owns settlement evidence, F12 moderation. References CORE_API_EVENTS_DATA.md.

## Model (CB-001)
One proposed cycle is a simple directed directed asset-transfer cycle involving k distinct authenticated principals (2 <= k <= 8 for MVP; generalized k<=12 future controlled by operator). Participant p_i provides asset a_i from its controlled listing to p_(i+1 mod k), receives a_(i-1 mod k), with explicit quantity and condition constraints. A participant MAY supply multiple assets only in future extension; MVP exactly one item or service per participant. Repeated user or repeated listing in a cycle INVALID. Multi-hop outside a single connected, closed directed cycle INVALID. Currency adjustments are optional separate obligations and DO NOT guarantee atomic settlement.
Cycle record fields: {cycle_id UUIDv7,tenant_id UUIDv7, revision BIGINT, proposal_digest bytes32, status enum(draft,proposed,collecting_consent,ready,locked,exchanging,reported_complete,cancelled,expired,disputed),expires_at timestamptz, lock_expires_at timestamptz|null, created_by uuid, created_at, updated_at}. Participant record {tenant_id,cycle_id,actor_id,slot smallint,listing_id,item_revision,receives_from_slot smallint,consent_state enum(pending,accepted,declined,revoked),consent_digest bytes32|null,consent_time|null,primary key (tenant_id,cycle_id,slot), UNIQUE(tenant_id,cycle_id,actor_id), UNIQUE(tenant_id,cycle_id,listing_id)}. Compensation obligation {obligation_id,cycle_id,payer_id,payee_id,currency,amount_minor positive bigint,purpose enum(balancing),quote_id nullable,verification_state enum(proposed,claimed,verified,failed,expired)}. This is a record of agreed responsibilities, not a wallet ledger.
Document canonical proposal JSON serialization must use deterministic RFC 8785 JCS and SHA-256 of versioned envelope; hashed material includes all participant IDs, exact item/condition/quantity revisions, ordered transfer edges, valuations, payment obligations, deadlines, exchange terms, quote IDs/expiries and public/private disclosure scope. Material revision creates new digest and resets ALL consent states to pending. Consent is tied to digest, not mutable ID alone.

## Candidate graph and search (CB-002)
Vertex = one eligible participant's listing/want combination under same tenant and privacy-safe search pool. Edge i->j exists if j is willing to receive i's item, condition/category/transport constraints satisfied, both unblocked and public sharing permission; eligibility rechecked on write. Do not expose edges from private/unconsented inventory. Deduplicate simple cycles by canonical rotation of participant UUIDv7 sequence. Deterministically sort vertices and neighbor edges by stable IDs for repeatable search results.
MVP: bounded depth-first enumeration of simple directed cycles length 2..8, stop at 50,000 explored edges or 250 ms CPU per discovery request, at most 500 vertices and 2,000 candidate edges for one user's search region. Standard DFS worst-case exponential in k; complexity O(V+E+number_of_enumerated_paths*k) within explicit budgets. Truncated result MUST include incomplete=true and reason SEARCH_BUDGET_EXCEEDED, never claim no match. Sort feasible proposals by unanimous-constraint satisfaction then deterministic cost/compatibility score; avoid hidden payment optimization or 'fair price' guarantees.
Three-party A->B->C->A and four-party A->B->C->D->A use same generalized matcher with k=3/4 filter and same validation, no separate inconsistent engine. Two-party A->B->A is a 2-cycle. General N cycles have exactly N directed edges and all participants distinct. Scope expansion beyond k8 requires chaos/performance/abuse signoff.

## State machine (CB-003)
draft -> proposed -> collecting_consent -> ready -> locked -> exchanging -> reported_complete; proposed/collecting_consent/ready -> cancelled/expired; locked/exchanging -> disputed/recovery_required (represented as disputed with resolution_state), or reported_complete only after each party's handoff assertion. Any participant decline before lock cancels proposal; revocation before lock invalidates ready and releases holds; after lock creates dispute/recovery, not silent transfer changes. A proposal revision always returns to collecting_consent and invalidates prior signatures. Terminal states immutable except append-only resolution evidence.
Preconditions lock: current digest valid, all N distinct participants have accepted current digest, none blocked/suspended, listings owner-revision still match, amounts and FX quotes unexpired, inventory free, deadline future, tenant policy enables cycles, no unresolved sanctions. Atomic local transaction sorts listing IDs ascending, SELECT FOR UPDATE, verifies revision and exclusivity then creates short-lived reservations and CAS advances cycle revision/status with outbox; no distributed lock across federated instances. Cross-relay physical asset custody is explicitly NOT atomic.
Consent POST /api/v1/cycles/{id}/consents {proposal_revision:int64,proposal_digest:hex64,decision:"accept"|"decline"} with If-Match and Idempotency-Key; only named account can consent, server binds account from session. GET /api/v1/cycles/{id} only participants or authorized moderator; redacted participant data per disclosure ACL. POST /api/v1/cycles/{id}:lock only orchestrator after unanimous consent; user endpoint must not bypass preconditions. POST :cancel by eligible party; POST /api/v1/cycles/{id}/attestations records own delivery/receipt assertion, cannot issue others' assertions. Response 409 PROPOSAL_CHANGED if digest/revision mismatch; 410 EXPIRED; 409 UNANIMOUS_CONSENT_MISSING; 409 ITEM_STALE; 409 RESOURCE_RESERVED; 423 MODERATION_HOLD.

## Mixed-value barter (CB-004)
Parties may mutually agree compensations, never silently calculate debts. Monetary obligations use ISO4217 integer minor units, total per currency net to zero within agreement (every payer matches payee). Cross-currency quote: {quote_id,base,quote,rate_num positive BIGINT,rate_den positive BIGINT,source_id,observed_at,expires_at,max_age_seconds<=900}; convert via integer rational multiplication with intermediate arbitrary-precision integers and round half-even once at obligation boundary; write displayed exact rounding deltas. Reject unknown exponent, stale quote, overflow, currency policy violation, negative payments, missing payer acceptance. A third-party crypto transfer can be claimed or verified independently and may still be reversed/reorged; NEVER release other parties' assets on claim alone. Default MVP only same-currency fiat price compensation recorded as off-platform claim; crypto+multi-currency balancing deferred until chain/FX verification specs reviewed.

## Failure, security, UX (CB-005)
Expired reservations released idempotently by leases and periodic sweeper; lease expiry is not real-world asset recovery. On any dropout after physical handover, freeze further orchestration, notify every party discreetly, open independent case and append evidence. No auto-reroute to a substitute; require a new proposal and unanimous re-consent. Offline consent is local draft only until authenticated server response; show 'Not submitted', never mark ready.
Abuse controls: limits candidate discovery by account/region/time, graph leakage adversarial probes, block lists, Sybil/spam challenge, per-tenant rate 20 graph queries/hour/account default, avoid returning private participant identities without consent. Moderation flags lock cycles; event payload IDs only. Display sequential transfer summary, explicit condition and money terms, per-party commitments, compact keyboard-accessible consent matrix, screenreader status and deadline.
