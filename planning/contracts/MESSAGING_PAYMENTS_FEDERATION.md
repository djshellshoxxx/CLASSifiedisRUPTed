# Messaging, payment verification and federation interop
Status: PROPOSED, not validated. Owners: F08 private messages, F09 payment evidence, F11 federation, F10 retention, F16 cryptography.

## Messaging and encryption (MPF-001)
Thread {id,tenant_id,subject_type enum(listing,offer,cycle,case),subject_id,created_by,created_at,state enum(open,blocked,archived),revision}. Membership {thread_id,actor_id,joined_at,left_at,role}. Message {id,thread_id,sender_id,client_message_id,ciphertext_bytes,algorithm,key_epoch,created_at,server_sequence,deleted_at}. UNIQUE(thread_id,sender_id,client_message_id); ciphertext size 1..65536; attachments max 10 MiB via F15 object storage, virus scanning before download, allowed file types by media parser not extension.
MVP confidential relay transport with TLS, encryption at rest and strict tenant+thread ACL. Do NOT claim end-to-end encryption until per-device encryption, key discovery, backups, rotation, multi-device recovery, verification, metadata and abuse-reporting tradeoffs are comprehensively specified and tested; mark E2EE future. Relay can access MVP message plaintext for delivery and lawful/report-based moderation subject to policy; UI privacy disclosure must accurately reflect this. Authenticated server assigns monotonic server_sequence per thread within SQL transaction, preserves cursor order; duplicates idempotently return original message. Deleted messages tombstoned in thread, not restored through federation replays. Membership changes deny subsequent reads except explicit archive rights. Reported messages may be escalated to moderation case with user consent or separate legal basis; no blanket moderator inbox access.
POST /api/v1/threads (participants must consent or be allowed by anti-spam policy); POST /api/v1/threads/{id}/messages; GET with cursor and membership check; event message.sent contains thread ID and server_sequence but never body/attachment secret. P95 send ack 500ms, catchup 2s at 99th percentile under nominal conditions. Offline drafts not sent until server ACK; keyboard focus management and unread status SR announcement; users can mute/block.

## Settlement evidence (MPF-002)
PaymentClaim {claim_id,tenant_id,proposal_id,claimant_actor_id,payer_actor_id,payee_actor_id,rail enum(cash,bank_direct,crypto_external,card_external),currency,amount_minor,reference_fingerprint,claim_status enum(claimed,withdrawn,disputed),created_at}; Verification {verification_id,claim_id,verifier_kind enum(provider_webhook,chain_observer,manual_counterparty),verifier_id,verified_status enum(unverified,observed,confirmed,revoked,failed),observed_at,proof_digest,confirmations integer|null,network|null,external_id|null,provenance}. Never interpret browser redirect, screenshot, unsigned webhook or buyer statement as independently confirmed funds. Provider webhooks require verifiable signature, allowlist of event types and provider-side fetch as necessary; deduplicate external event IDs. External chain observer must choose chain-specific confirmation and reorg policy in dedicated F09.S01.M03 spec before feature enablement. Unknown/reorg downgrades verified status, emits payment.verification_revoked, opens case for already handoff goods. Cash counterparty acknowledgement remains bilateral claim, NOT independently verified. No wallet private keys, signing keys, card PAN, bank logins or custody stored by ClassRup.
POST /api/v1/claims (participant), GET /api/v1/claims/{id} (subject participants), verification internal-only signed webhook/observer. 422 amount/currency mismatch, 403 unauthorized claim, 409 mismatched proposal revision, 503 external verifier outage; never mint a verification event on claim. Every UI receipt labels 'claimed', 'counterparty acknowledged', 'observed externally' or 'confirmed by source', with sources and revocation risk.

## Federation import/export (MPF-003)
Federation is optional tenant opt-in and default OFF for MVP. Define canonical FedRecordV1 {version:1,record_id:UUIDv7,origin_peer_id,origin_object_id,owner_pubkey_id,kind enum(listing_public,tombstone,profile_public),aggregate_revision:uint64,created_at,expires_at,visibility:"public",payload:approved_public_projection,prev_digest:hex|null,signature_alg:"Ed25519",signature_base64url}. Encode using JCS canonicalization; signature covers domain-separation prefix "classrup-fed-v1\n" + all signed envelope fields except signature, bytes UTF-8; pin Ed25519 identity keys and peer trust config. Rejected on schema/type violation, unsupported version, revoked key, invalid signature, blocklisted peer, old revision, excessive clock skew (>5min future), expired record, tampering or private field in projection. Quarantine malicious peers; never execute imported content as scripts or blindly mirror HTML/image URLs; image proxy scanning and safe MIME type.
Uniqueness index (tenant_id,origin_peer_id,origin_object_id), versions strictly increasing per origin, tombstones dominate older replay, retain tombstone digest/expiry at least 180 days where policy allows, detect split-brain conflicting signed same-version digests -> quarantine + operator notice rather than arbitrary winner. Outbound: allowlisted public listing/profile fields only; explicit user consent and private address stripping before signing. Inbound: signature authenticity proves asserted origin key, not claim truth or goods legitimacy; local F12 moderation MUST gate indexing. Peer may harvest graph and location metadata; rate limits, minimal disclosure, pseudonym rotation and delayed fanout considered, not anonymity guarantees.
POST /api/v1/federation/inbox peer-authenticated, <=64 KiB envelope, accept 202 to asynchronous quarantined validation, status/receipts returned with opaque IDs; no anonymous bulk export of private graph. GET /api/v1/federation/outbox?cursor uses peer ACL and pagination with signed cursor. Retry exponential backoff with full jitter capped 6h, dead-letter after 20 attempts, at-least-once delivery and idempotent inbox. Peer disconnected for >30d requires signed snapshot reconciliation subject to local moderation and tombstones; do not import unresolved conflicts.
